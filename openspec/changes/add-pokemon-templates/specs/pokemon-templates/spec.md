# Spec Delta

## Purpose

让用户把单只宝可梦的配置（规则版本、形态、性格、招式、道具与 IV/EV 或能力点）保存为可命名、
可复用的个人模板；未登录时先存于本机、可随时建立与查看，登录后持久化到账号并跨设备同步。

## ADDED Requirements

### Requirement: 编辑单只宝可梦的配置
系统 SHALL 提供一个配置编辑器，让用户为单只宝可梦选择规则版本（标准版 / Champions）、含形态的
宝可梦、性格、至多 4 个招式与一个道具，并按规则版本编辑对应的养成字段。标准版编辑个体值 IV 与
努力值 EV；Champions 版编辑能力点 SP。配置 MUST 使用稳定数值 id 存储（宝可梦 id 含形态、性格用
PokeAPI id、招式与道具用 PokeAPI id）。

#### Scenario: 选择宝可梦与形态
- **WHEN** 用户在编辑器中选择一只宝可梦及其某个形态
- **THEN** 系统记录该形态对应的单一宝可梦 id（默认形态为物种号，其它形态为 10000+ 的 id），并按它索引立绘与可学招式

#### Scenario: 招式去重且不超过 4 个
- **WHEN** 用户选择的招式超过 4 个或与已选招式重复
- **THEN** 系统只保留至多 4 个招式，重复招式只保留一次且维持原有顺序

#### Scenario: 切换规则版本切换养成字段
- **WHEN** 用户在标准版与 Champions 版之间切换
- **THEN** 编辑器在 IV/EV 输入与能力点 SP 输入之间切换，且 Champions 版的等级固定为 Lv50

#### Scenario: 养成值取值受限
- **WHEN** 用户输入超出范围的 IV、EV 或能力点（IV 单项 >31；EV 单项 >252 或六项合计 >510；能力点单项 >32 或合计 ≠66）
- **THEN** 系统将其钳制到合法范围或阻止该输入，使待保存数据始终满足取值约束

#### Scenario: Champions 版仅允许 21 种性格
- **WHEN** 用户在 Champions 规则下选择性格
- **THEN** 系统只提供 21 种合法性格（不含 Hardy / Docile / Bashful / Quirky）

### Requirement: 实时预览能力值
系统 SHALL 在用户编辑配置时实时计算并展示六项能力值。用于计算的等级仅作为本地预览参数，MUST NOT
写入模板内容；标准模板默认以 Lv50 预览，Champions 模板固定 Lv50。

#### Scenario: 修改养成值即时更新能力
- **WHEN** 用户调整性格、IV/EV 或能力点
- **THEN** 六项能力值立即按当前配置重新计算并展示

#### Scenario: 调整预览等级不影响保存内容
- **WHEN** 用户在标准版改变预览等级
- **THEN** 预览能力值随之变化，但保存的模板内容中不包含等级字段

### Requirement: 未登录可用的本地草稿
系统 SHALL 允许未登录用户新建、查看、编辑模板并把草稿保存到本机存储；应用重启后这些草稿 MUST 仍然
存在并可在列表中打开继续编辑。

#### Scenario: 未登录保存草稿
- **WHEN** 未登录用户在编辑器中选择「保存草稿」
- **THEN** 系统把该模板写入本机存储并返回列表，列表中可见该条

#### Scenario: 重启后恢复草稿
- **WHEN** 用户退出并重新打开应用后进入模板列表
- **THEN** 之前保存在本机的草稿仍被列出，打开后配置完整还原

#### Scenario: 列表对本地与云端条目统一可用
- **WHEN** 未登录用户进入模板列表
- **THEN** 系统直接展示本机保存的全部模板，无需登录、也不发起网络请求

### Requirement: 标注模板的同步状态
系统 SHALL 为每个模板标注同步状态：从未上云的草稿为「未存档」，已上云后本地又改动为「待同步」，
与账号一致为「已同步」。

#### Scenario: 列表展示各状态
- **WHEN** 列表中同时存在本地草稿、被改动过的云端模板和正常云端模板
- **THEN** 它们分别显示「未存档」「待同步」「已同步」标记

### Requirement: 保存模板到账号
系统 SHALL 在用户触发「保存」时把模板持久化到账号：已登录直接提交，未登录先完成登录再提交；新建走
POST、已存在走 PUT。保存成功后 MUST 以服务端返回的 id 作为该模板之后更新的依据，并把状态置为「已同步」。

#### Scenario: 已登录保存新模板
- **WHEN** 已登录用户对一条新模板点击「保存」
- **THEN** 系统提交 POST，成功（201）后记录返回的 id，该条状态变为「已同步」

#### Scenario: 未登录保存时先登录
- **WHEN** 未登录用户点击「保存」
- **THEN** 系统弹出登录界面；登录成功后继续提交该模板，用户取消登录则停留在编辑页且不丢弃当前改动

#### Scenario: 更新已存在的模板
- **WHEN** 用户对一条已有 id 的模板点击「保存」
- **THEN** 系统提交 PUT（携带完整模板内容与名称），成功后状态变为「已同步」

### Requirement: 处理保存与同步错误
系统 MUST 按后端返回的稳定错误码分支处理，而不是匹配错误文案：401 走会话恢复后重试；400（内容不合法）
提示修正；404（模板不存在或非属主）从本地列表移除；409（重名或数量到上限）提示改名或清理。

#### Scenario: 模板名称冲突
- **WHEN** 保存时后端返回 409 / CONFLICT（名称已存在）
- **THEN** 系统提示用户更换名称，且保留当前编辑内容与模板 id

#### Scenario: 模板已不存在
- **WHEN** 打开或保存时后端返回 404 / NOT_FOUND
- **THEN** 系统从本地列表移除该模板

#### Scenario: 访问令牌失效
- **WHEN** 请求返回 401 / UNAUTHENTICATED
- **THEN** 系统按会话恢复流程刷新令牌并重试原请求

### Requirement: 退出编辑时处理未保存改动
系统 SHALL 在用户离开编辑页时检查改动：无改动直接离开；有改动则让用户选择「保存草稿」「放弃更改」或
「取消」。

#### Scenario: 有改动时退出
- **WHEN** 用户在存在未保存改动时触发返回
- **THEN** 系统弹出选择：保存草稿（写入本机）、放弃更改（丢弃改动）、取消（留在编辑页）

#### Scenario: 无改动时退出
- **WHEN** 用户未做任何改动即触发返回
- **THEN** 系统直接返回上一页，不弹出提示

### Requirement: 删除模板
系统 SHALL 允许删除模板：未上云的本地草稿直接从本机删除；已上云模板的删除在登录后提交 DELETE，未登录
时先标记、待登录后补删。

#### Scenario: 删除本地草稿
- **WHEN** 用户删除一条「未存档」草稿
- **THEN** 系统立即从本机移除该条，不要求登录

#### Scenario: 删除已同步模板
- **WHEN** 用户删除一条「已同步」模板
- **THEN** 已登录时系统提交 DELETE 并从列表移除；未登录时先标记为待删除，登录后补做删除

### Requirement: 从能力值计算器带入配置新建模板
系统 SHALL 在能力值计算器中提供「存为模板」入口，把当前计算所用的配置带入模板新建编辑页；计算器本身
保持只用于计算能力，不承担保存管理。

#### Scenario: 计算器跳转并预填
- **WHEN** 用户在能力值计算器点击「存为模板」
- **THEN** 系统打开模板新建编辑页并预填当前宝可梦、规则版本、性格与 IV/EV 或能力点，之后按保存 / 草稿流程处理
